# Demographics

**Primary sources:** Population synthesis outputs, REMI model exports, rate tables (CSV/Excel)  
**Build scripts:** `forecast_controls/` pipeline (Steps 1–7), `group_quarters/gq_synth.py`

This domain covers the base-year synthetic population (households, persons, group quarters), annual household growth control totals from REMI, and supporting rate and target tables.

## Households & Persons

### `households`

Base-year synthetic household table. Generated by PopulationSim and placed into buildings using voter registration data as a placement guide.

**Index:** `household_id` (unique)

| Column | Type | Rules | Notes |
|---|---|---|---|
| `household_id` | int32 | unique, no null | |
| `building_id` | int32 | join → `buildings`, no null | Placement result; -1 = unplaced |
| `persons` | int8 | range [1–20], no null | Household size |
| `workers` | int8 | range [0–18], no null | Employed workers |
| `age_of_head` | int8 | range [15–100], no null | Age of head |
| `income` | float64 | no null | Annual income ($); negatives set to 0 |
| `children` | int8 | range [0–14], no null | Children under 18 |
| `cars` | int8 | values: 0–6 | Vehicle count |
| `race_id` | int8 | values: 1,2,3,4 | 1=White, 2=Black, 3=Asian, 4=Other |

**Common issues:**
- `workers > persons` — invalid combination; flag in synthesis output
- `building_id = -1` — unplaced households are assigned to pseudo-buildings at startup, then placed by the HLCM
- Negative income — set to 0 in the build pipeline (intentional)

### `persons`

All individuals in base-year synthetic households. One row per person.

**Index:** `person_id` (unique)

| Column | Type | Rules | Notes |
|---|---|---|---|
| `person_id` | int32 | unique, no null | |
| `household_id` | int32 | join → `households`, no null | |
| `age` | int8 | range [0–94], no null | |
| `sex` | int8 | values: 1, 2 | 1=male, 2=female |
| `race_id` | int8 | values: 1,2,3,4 | |
| `worker` | int8 | values: 0, 1 | 1=employed |
| `relate` | int8 | values: 0–15 | Relationship to head (ACS codes); 0=head |
| `member_id` | int8 | range [1–20], no null | Position in household (1=head) |
| `industry` | int8 | no null | Aggregated NAICS industry |
| `school_grade` | int8 | no null | Enrolled grade; -1=not enrolled |

**Common issues:**
- Persons with `household_id` not in `households` — orphaned persons; drop or investigate
- Each household should have exactly one `relate = 0` (the head)

## Control Totals & Population Forecasts

### `annual_household_control_totals`

Drives how many households exist in each large area × demographic segment each year. The most critical table for forecast outcomes.

**Index:** `year`  
**Generated by:** `forecast_controls/` pipeline (Steps 1–7), which converts REMI population exports into segmented household targets

**Columns:**

| Column | Type | Allowed Values | Notes |
|---|---|---|---|
| `year` | int16 | must cover all forecast years | Index |
| `large_area_id` | int16 | 8 valid codes | One of the 8 modeling zones |
| `age_of_head_min/max` | int8 | bracket bounds | `-1` = open-ended upper bound |
| `persons_min/max` | int8 | bracket bounds | |
| `workers_min/max` | int8 | bracket bounds | |
| `income_min/max` | int32 | bracket bounds | |
| `children_min/max` | int8 | bracket bounds | |
| `cars_min/max` | int8 | bracket bounds | |
| `race_id` | int8 | 1,2,3,4 | |
| `total_number_of_households` | int16 | no null | Target HH count for this segment × year |

**The `-1` sentinel** in `_max` columns means "no upper bound" (open-ended category).

**Common issues:**
- Missing years — all forecast years must be present; run the pipeline for any missing years
- Segment totals should sum to plausible regional totals — cross-check against `remi_pop_total`

### `remi_pop_total`

Total population by large area × year, directly from REMI. Used to calibrate HH controls and as a model input for population scaling.

**Index:** `large_area_id` (unique)  
**Structure:** 8 rows × year columns (one column per simulation year)

| Column | Type | Notes |
|---|---|---|
| `large_area_id` | int16 | Row index |
| one column per year | int32 | Total population including group quarters |

**Update procedure:** Export regional population totals from REMI by large area × year. Save with `large_area_id` as index and one column per year.

### `mcd_total`

Target household counts by MCD × year. Used by `mcd_hu_sampling` to control city-level household growth.

**Index:** `mcd` (MCD code)  
**Structure:** One row per MCD × year columns  
**Derived from:** `annual_household_control_totals` aggregated to MCD level; see `forecast_controls/step3_mcd_interpolate.py`

## Rate & Target Tables

### `annual_relocation_rates_for_households`

Probability of a household relocating in a given year, by age of head and income.

**Source:** Excel rate table — path in `config/files.yaml`

| Column | Type | Allowed Values |
|---|---|---|
| `age_min/max` | int8 | age bracket bounds; -1=open-ended |
| `income_min/max` | int32 | income bracket bounds; -1=open-ended |
| `probability_of_relocating` | float32 | no null |

**Note:** In the simulation this rate is scaled by 0.2 (20% of raw rate). Households in event/landmark buildings are protected from relocation.

### `income_growth_rates`

Annual income growth multiplier by large area. One row per year, one column per large area.

**Index:** `year`  
**Source:** CSV — path in `config/files.yaml`

### `target_vacancies`

Target residential and non-residential vacancy rates by large area × year. Used by the developer model to determine how much new construction to generate.

**Source:** Excel — path in `config/files.yaml`

| Column | Type | Notes |
|---|---|---|
| `large_area_id` | — | 8 valid codes |
| `year` | — | All forecast years |
| `res_target_vacancy_rate` | float32 | e.g., 0.05 = 5% |
| `non_res_target_vacancy_rate` | float32 | |

### `target_vacancies_mcd`

City-level residential vacancy targets. Takes precedence over large area targets when present.

**Index:** `cityid`  
**Source:** Excel — path in `config/files.yaml`

## `group_quarters`

Group quarters persons — one row per person living in a non-household arrangement (dormitory, nursing home, prison, military barracks). Tracked separately from regular households; not subject to HLCM.


One row per group quarters **person**. Assigned to a building that is a known GQ facility.

**Index:** `personid` (unique)  
**Generated by:** `group_quarters/gq_synth.py`

| Column | Type | Allowed Values | Notes |
|---|---|---|---|
| `personid` | int32 | unique, no null | |
| `building_id` | int32 | join → `buildings`, no null | GQ facility building |
| `gq_code` | int16 | 101,201,301,401,501,701,789 | GQ type (see below) |
| `age` | int8 | no null | |
| `race_id` | int8 | 1,2,3,4 | |
| `type` | object | — | GQ type label |

**GQ type codes:**

| Code | Type |
|---|---|
| 101 | College/University dormitory |
| 201 | Military quarters |
| 301 | Correctional facilities |
| 401 | Nursing/assisted living |
| 501 | Other institutional |
| 701 | Other non-institutional |
| 789 | Other/unknown |

Target GQ population counts by city × year. Used by `gq_pop_scaling_model` to scale GQ population each simulation year.

**Index:** `cityid`  
**Source:** CSV derived from Excel source — paths in `config/files.yaml`

| Column | Type | Rules |
|---|---|---|
| `city_id` | int32 | no null |
| `count` | int32 | no null |
| `year` | int16 | range covers all forecast years, no null |

## Update Checklist (New Forecast Cycle)

- [ ] Get new REMI population export by large area × age × gender; run `forecast_controls/step1_scale_remi_pop.py`
- [ ] Run the full HH control total pipeline (Steps 1–7 in `forecast_controls/`)
- [ ] Update `remi_pop_total` with new REMI population totals
- [ ] Update `mcd_total` from MCD interpolation step
- [ ] Review and update vacancy rate tables if market conditions warrant
- [ ] Update GQ control totals and re-run `gq_synth.py` if base year changes
- [ ] Validate: all forecast years must have rows in `annual_household_control_totals`
- [ ] Run validation: `python -m input_validation.cli --hdf <output hdf>`
