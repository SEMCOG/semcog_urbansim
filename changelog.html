    Changelog¶

    A time-ordered record of substantive changes to the forecast data pipeline and this wiki's documentation of it.

    Maintenance: add the newest dated block to the top, one short bullet per change.

    June 2026 — three-HDF compilation and PCE correction¶

    Compiled existing forecast input data into the three HDF files this wiki documents (docs/index.md#output-files).

    Data compiled:

    • access_indicators.h5 — built from the three accessibility indicator CSVs (walk/bike/drive), with the documented fill values (95/125/155 min for unreachable near-max variables, 0 for cumulative/gravity variables) applied.
    • semcog_networks.h5 — renamed from semcog_2050_networks.h5 (no data change); filenames in this pipeline don't encode forecast vintages.
    • forecast_data_input.h5 — added points_of_interest_by_category (renamed from the unused poi HDF key — the live poi orca table reads pois.csv directly and never read this key), remi_hh_pop, acs_household_change_by_block_group, remi_pce_growth_rate, and taz_demographic_snapshots (2010 + 2015, built with the same forecast_estimation.utils.data_utils loaders init_taz_hlcm_trend_by_year already uses at simulation startup, for consistency with the live computation).

    PCE correction (verified against dataset.py/models.py, not assumed):

    • remi_pce_growth_rate only feeds construction-cost inflation (cost_shifter_callback) — it does not drive property-value appreciation as a previous version of this page claimed. That's a separate, large-area-specific series (remi_pi_growth_rates, personal income).
    • remi_pce_growth_rate is now produced by a new script, forecast_data_input/development_context/PCE_growth_rate.py, from a newer REMI export (SEMCOG Region 2055 Preliminary Forecast) than the one behind income_growth_rates — the two are no longer (and weren't really) the same REMI run.
    • dataset.py now loads remi_pce_growth_rates from the HDF table instead of computing it live from REMI xlsx files. The old code had a latent bug: it silently kept only the first large area's PCE series (Wayne suburbs) and discarded the other 7 while believing it was a regional figure. The new table is a household-population-weighted average across all 8 large areas.

    New folder: forecast_data_input/development_context/ — home for REMI-rate extraction scripts in the Development & Context domain (starting with PCE_growth_rate.py). It does not mirror the wiki domain 1:1 — SQL-sourced tables (crime_rates, schools, demolition_rates, events) stay in model_input/landuse.py, and construction costs remain a static delivered CSV. See that folder's README.md.

    Validation & data fix (full-year test run):

    • A 1-year (2020→2021) simulation against all three new HDF files completed cleanly. The new tables loaded and were consumed as expected: PCE growth rates read at startup (range 1.44%–6.78%), accessibility variables sourced from access_indicators.h5, and the emptied pseudo tables produced a clean no-op (2021 households show zero unplaced and zero pseudo building_ids).
    • remi_hh_pop year-column dtype fixed — the table was first written with integer year columns (2020, 2021, …), but the consuming code looks years up by string, and every other wide-format (year-as-column) table in the file (remi_pop_total, income_growth_rates, target_vacancies_mcd) uses string column labels. The mismatch caused an immediate failure on the first transition step. remi_hh_pop columns are now strings, matching the file-wide convention. Build rule: wide tables keyed by year must use string year columns. (PCE_growth_rate.py's remi_pce_growth_rate is year-indexed, not year-columned, so it is unaffected.)
    • Empty-table write note — pseudo_building_2020/pseudo_parcel_2020 must be written with format='fixed', not format='table': PyTables silently drops a zero-row frame written in table format, which removes the key entirely instead of leaving an empty table.
